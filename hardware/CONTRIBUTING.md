# Hardware Collaboration Guide

Pumpkin 팀원이 새 부품을 추가하거나 실제 배선을 변경할 때 따르는 공통 절차입니다.

> 핵심 규칙: **작업 전에 부품 ID를 확인하고, 작업 후 같은 ID로 부품 사양·전원·배선·테스트 결과를 함께 갱신합니다.** 모르는 값은 추측하지 말고 `TODO` 또는 `확인 필요`로 남깁니다.

## 문서와 엑셀의 역할

- 엑셀: 조립 현장에서 빠르게 입력하는 부품·배선·변경 기록
- GitHub: 확인이 끝난 현재 사양과 배선을 관리하는 기준 문서
- 두 곳은 반드시 동일한 `부품 ID`를 사용합니다.
- 엑셀의 `GitHub 반영` 열이 `완료`가 될 때까지 작업이 끝난 것으로 보지 않습니다.

## 작업 전에 반드시 확인

1. `components.yaml`에서 기존 부품 ID가 있는지 검색합니다.
2. `wiring.md`에서 이미 배정된 핀·포트·채널인지 확인합니다.
3. 전원 연결이라면 `power-budget.md`에서 전압, 최대전류, 극성, 공통 GND, 퓨즈 여부를 확인합니다.
4. 전원이 켜진 상태에서는 배선을 바꾸지 않습니다.
5. 전압·극성·핀맵 중 하나라도 불확실하면 연결하지 않고 `확인 중`으로 기록합니다.

## 1. 새 부품을 추가할 때

### A. 부품 ID 만들기

- 영문 대문자와 밑줄만 사용합니다.
- 같은 실제 부품에 ID를 두 개 만들지 않습니다.
- 동일 모델이 여러 개여도 물리적으로 따로 장착·연결되면 번호를 나눕니다.

| 분류 | 권장 형식 | 예시 |
|---|---|---|
| 메인 컴퓨터 | `COMPUTE_이름` | `COMPUTE_JETSON_MAIN` |
| 제어 보드 | `MCU_이름` | `MCU_ESP32_MAIN` |
| 모터·서보 | `MOTOR_모델_번호`, `SERVO_모델_번호` | `SERVO_MG996R_02` |
| 센서 | `SENSOR_모델_위치` | `SENSOR_TOF_FRONT` |
| 오디오 | `AUDIO_종류_이름` | `AUDIO_SPEAKER_MAIN` |
| 디스플레이 | `DISPLAY_이름` | `DISPLAY_LCD_ILI9488` |
| 전원 | `POWER_전압_용량` | `POWER_5V_15A` |
| 전원 레일 | `RAIL_용도` | `RAIL_SERVO` |

### B. 엑셀에 먼저 기록

`부품 목록` 시트에 한 줄을 추가합니다.

최소 필수 항목:

- 부품 ID
- 분류
- 역할
- 제조사·정확한 모델명
- 수량
- 보유 상태
- 정격전압
- 최대전류 또는 `확인 필요`
- 제어·통신 방식
- 연결 대상
- 전원 레일
- 작업자와 수정일

제품 전체 사진과 앞·뒤 라벨 사진도 남기고, 데이터시트나 제조사 문서 링크를 기록합니다. 쇼핑몰 설명만으로 전기 사양을 확정하지 않습니다.

### C. GitHub 문서 갱신

1. `components.yaml`에 새 부품 항목을 추가합니다.
2. 전기를 사용하는 부품이면 `power-budget.md`에 한 행을 추가합니다.
3. 실제 연결 계획이 있으면 `wiring.md`에 `예정` 상태로 추가합니다.
4. 아직 확인할 것이 있으면 `TODO.md`에 체크 항목을 추가합니다.
5. 엑셀의 `GitHub 반영`을 `완료`로 바꾸고 PR 또는 커밋 링크를 남깁니다.

## 2. 부품을 연결하거나 배선을 바꿀 때

### 연결 전

1. 출발·도착 부품 ID를 확인합니다.
2. 출발 포트와 도착 포트, 신호 방식, 로직 전압을 확인합니다.
3. 전원선이면 입력전압, 최대전류, 극성, 케이블 허용전류를 확인합니다.
4. 별도 전원을 쓰는 장치끼리 신호를 주고받으면 공통 GND 필요 여부를 확인합니다.
5. 엑셀 `연결표`에 상태를 `예정` 또는 `확인 중`으로 먼저 기록합니다.

### 연결 후

1. 전원을 넣기 전 멀티미터로 출력전압과 극성을 확인합니다.
2. 처음에는 장치 하나만 단품 테스트합니다.
3. 성공하면 엑셀과 `wiring.md`의 상태를 `단품 성공`으로 바꿉니다.
4. 여러 장치가 함께 동작하면 `통합 성공`으로 바꾸고 시험 조건을 기록합니다.
5. 배선이 바뀌면 `wiring.md`의 `배선 변경 기록`과 엑셀 `변경 기록`을 모두 작성합니다.
6. 전류나 전원 레일이 달라졌으면 `power-budget.md`도 함께 수정합니다.

## 3. 테스트 상태 사용 규칙

| 상태 | 의미 |
|---|---|
| `예정` | 연결 관계만 정했고 아직 배선하지 않음 |
| `확인 중` | 전압·핀·케이블 중 확인할 것이 남음 |
| `단품 성공` | 해당 장치만 연결해 정상 동작 확인 |
| `통합 성공` | 다른 장치와 동시에 동작 확인 |
| `문제` | 연결 또는 동작 이상이 있어 원인 확인 필요 |

`단품 성공`이나 `통합 성공`에는 테스트 날짜, 작업자, 시험 조건, 결과를 반드시 함께 적습니다.

## 4. GitHub에서 제출하는 방법

GitHub 웹 화면만 사용해도 됩니다.

1. 수정할 파일에서 연필 아이콘을 누릅니다.
2. 필요한 내용을 수정합니다.
3. 커밋 메시지를 `hardware: 변경 내용` 형식으로 씁니다.
4. 가능하면 새 브랜치를 만들고 Pull Request를 엽니다.
5. 전원·핀 배정 변경은 다른 팀원 한 명이 확인한 뒤 병합합니다.

브랜치 이름 예시:

- `hardware/add-camera`
- `hardware/connect-lcd`
- `hardware/update-servo-power`

커밋 메시지 예시:

- `hardware: add front camera specifications`
- `hardware: assign PCA9685 servo channels`
- `hardware: record 5V rail current test`

## 5. Pull Request 체크리스트

- [ ] 기존 부품 ID와 중복되지 않음
- [ ] 모델명과 옵션을 제품 라벨로 확인함
- [ ] 전압·전류·극성을 확인함
- [ ] `components.yaml`을 수정함
- [ ] 필요 시 `power-budget.md`를 수정함
- [ ] 필요 시 `wiring.md`를 수정함
- [ ] 남은 확인 사항을 `TODO.md`에 적음
- [ ] 단품 또는 통합 테스트 결과를 기록함
- [ ] 엑셀에도 같은 부품 ID로 반영함

## 팀 채팅에 보낼 짧은 안내문

> 부품을 새로 추가하거나 배선을 바꾸기 전에 기존 부품 ID와 포트 배정을 먼저 확인해주세요. 새 부품은 엑셀 `부품 목록`에 등록하고, 연결은 `연결표`에 `예정/확인 중`으로 먼저 적어주세요. 작업 후에는 같은 부품 ID로 GitHub의 `components.yaml`, `power-budget.md`, `wiring.md`, `TODO.md` 중 해당 파일을 같이 수정하고 테스트 결과를 남겨주세요. 전압·전류·극성·핀맵이 불확실하면 추측해서 연결하지 말고 `확인 필요`로 남겨주세요. 전원이나 핀 배정 변경은 다른 팀원 한 명이 확인한 뒤 반영해주세요.
