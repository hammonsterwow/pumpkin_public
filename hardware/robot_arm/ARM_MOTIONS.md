# Pumpkin 로봇팔 동작 정의

Pumpkin 로봇팔에 실제 구현한 기본 제스처 5가지를 정리한다.

현재 로봇팔의 기본 동작은 **차렷, 오른쪽, 왼쪽, 모르겠어요, 인사**의 5가지이며, 이후 ROS2/Jetson에서 팔 동작을 호출할 때도 이 의미를 기준으로 통일한다.

## 1. 기본 동작 목록

| 번호 | 동작 | 권장 명령명 | 용도 |
|---:|---|---|---|
| 1 | 차렷 | `HOME` | 대기 상태 및 다른 동작의 시작·종료 기준 자세 |
| 2 | 오른쪽 | `POINT_RIGHT` | 로봇 기준 오른쪽 방향 안내 |
| 3 | 왼쪽 | `POINT_LEFT` | 로봇 기준 왼쪽 방향 안내 |
| 4 | 모르겠어요 | `UNKNOWN` | 질문을 이해하지 못했거나 판단이 어려운 상황을 팔 제스처로 표현 |
| 5 | 인사 | `GREETING` | 고객 접근 시 환영·인사 표현 |

> 방향 표현에서 `RIGHT`와 `LEFT`는 **로봇 자신의 기준**으로 정의한다. 사용자 시점과 혼동하지 않도록 코드와 문서에서 동일한 기준을 유지한다.

## 2. 동작별 정의

### 2.1 차렷 (`HOME`)

- 로봇팔의 기본 대기 자세이다.
- 전원 투입 후 초기 자세로 사용한다.
- 다른 팔 동작이 끝난 뒤 복귀하는 기준 자세로 사용한다.
- 장시간 대기 중 불필요한 동작을 하지 않도록 한다.

### 2.2 오른쪽 (`POINT_RIGHT`)

- 로봇 기준 오른쪽 방향을 팔로 가리키는 안내 동작이다.
- 매장 내 위치 또는 이동 방향을 안내할 때 사용할 수 있다.
- 예: 픽업 위치, 출구, 화장실 등 오른쪽 방향 안내.

### 2.3 왼쪽 (`POINT_LEFT`)

- 로봇 기준 왼쪽 방향을 팔로 가리키는 안내 동작이다.
- 매장 내 위치 또는 이동 방향을 안내할 때 사용할 수 있다.
- 예: 픽업 위치, 출구, 화장실 등 왼쪽 방향 안내.

### 2.4 모르겠어요 (`UNKNOWN`)

- 로봇이 사용자의 요청을 이해하지 못했거나 현재 정보만으로 판단하기 어려운 상황을 표현하는 동작이다.
- STT/NLU 인식 실패, 낮은 confidence, 비정형 질문 처리 실패 등과 연동할 수 있다.
- TTS의 재질문과 함께 사용하여 로봇이 현재 상태를 사용자가 직관적으로 이해하도록 한다.

예시:

```text
로봇: "잘 이해하지 못했어요. 다시 한 번 말씀해 주세요."
팔 동작: UNKNOWN
```

### 2.5 인사 (`GREETING`)

- 고객을 감지했을 때 수행하는 환영 동작이다.
- TTS 인사와 LCD 표정 출력과 함께 사용한다.
- 고객 접근 시 서비스 시작을 시각적으로 알려주는 역할을 한다.

예시:

```text
로봇: "안녕하세요. 주문 도와드릴게요."
팔 동작: GREETING
```

## 3. Jetson–ESP32 명령 규격

팔 동작 명령은 각 서보의 각도를 Jetson에서 직접 제어하기보다, **동작 이름을 ESP32에 전달하고 ESP32가 저장된 프리셋을 실행하는 방식**을 기본으로 한다.

```text
ARM,HOME
ARM,POINT_RIGHT
ARM,POINT_LEFT
ARM,UNKNOWN
ARM,GREETING
ARM,STOP
```

상태 응답 예시는 다음과 같다.

```text
ARM,ACK,GREETING
ARM,DONE,GREETING
ARM,ACK,POINT_RIGHT
ARM,DONE,POINT_RIGHT
ARM,ERROR,LIMIT,CH5
ARM,STOPPED
```

## 4. ROS2 연동 기준

ROS2의 판단/행동 계층에서는 상황에 따라 다음과 같이 팔 동작을 선택한다.

| 상황 | 팔 동작 |
|---|---|
| 로봇 대기 | `HOME` |
| 고객 접근 및 첫 인사 | `GREETING` |
| 오른쪽 위치 안내 | `POINT_RIGHT` |
| 왼쪽 위치 안내 | `POINT_LEFT` |
| 인식 실패·판단 불가·재질문 | `UNKNOWN` |
| 동작 완료 후 대기 전환 | `HOME` |

최종적으로 `arm_control_node`가 행동 명령을 ESP32에 전달하도록 통일한다.

## 5. 구현 원칙

- 실제 관절별 목표 각도와 이동 순서는 ESP32 펌웨어의 프리셋을 기준으로 관리한다.
- 문서와 ROS2에서는 관절 각도보다 `HOME`, `POINT_RIGHT`, `POINT_LEFT`, `UNKNOWN`, `GREETING`과 같은 **행동 의미**를 사용한다.
- 각 동작 전후에 충돌, 케이블 끼임, 서보 과부하가 없는지 확인한다.
- 필요하면 동작 종료 후 `HOME`으로 복귀하도록 한다.
- `STOP` 명령은 5가지 제스처와 별도로 안전을 위한 즉시 동작 중단 명령으로 유지한다.

## 6. 현재 구현 상태

2026-08-26 기준 로봇팔 기본 제스처는 다음 5가지로 정리한다.

1. 차렷
2. 오른쪽
3. 왼쪽
4. 모르겠어요
5. 인사

기존 문서에 있던 `ORDER_CONFIRM`, `POINT_PICKUP`, `GRIP_OPEN`, `GRIP_CLOSE` 등의 초안 동작명은 현재 기본 동작 정의로 사용하지 않는다. 필요한 서비스 행동은 위 5개 동작을 조합하거나 추후 별도 동작으로 추가한다.
