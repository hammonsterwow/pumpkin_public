# 한이음 Physical AI 무인매장 응대 로봇 - 사용 시나리오 흐름도

본 문서는 무인 커피 매장 로봇의 핵심 사용 시나리오를 처음 보는 사람도 이해할 수 있도록 정리한 흐름도입니다.

## UC-01 매장 직접 음성 주문

![UC-01 매장 직접 음성 주문 흐름](./UC-01_매장_직접_음성_주문_흐름.svg)

```mermaid
flowchart LR
    A[1. 로봇 앞 접근<br/>고객이 주문을 시작함] --> B[2. 환영 화면·인사<br/>주문 도와드릴게요]
    B --> C[3. 음성으로 주문<br/>메뉴·온도·수량·옵션 발화]
    C --> D[4. STT 변환<br/>음성을 텍스트로 변환]
    D --> E[5. ko-ELECTRA NLU 분석<br/>주문 의도·메뉴·수량·옵션 추출]
    E --> F[6. 주문 확인 화면/음성<br/>아이스 아메리카노 2잔 맞으신가요?]
    F --> G{주문 내용이 맞는가?}
    G -- 네 --> H[7. 주문 서버 전송]
    H --> I[8. DB 저장]
    I --> J[9. 주문 완료 안내<br/>주문이 완료되었습니다]
    G -- 아니오 --> K[다시 주문 안내]
    K --> C
    C -. 인식 실패·불명확 .-> K
```

### UC-01 핵심 설명

- 고객이 로봇 앞에 접근하면 로봇이 인사하고 주문을 요청합니다.
- 고객은 음성으로 메뉴, 온도, 수량, 옵션을 말합니다.
- STT가 음성을 텍스트로 변환하고, ko-ELECTRA 기반 NLU가 주문 정보를 추출합니다.
- 로봇은 주문 확인 화면과 음성으로 내용을 재확인합니다.
- 사용자가 맞다고 답하면 주문을 서버/DB에 저장하고 완료 안내를 제공합니다.
- 인식 실패 또는 주문 내용 불일치 시 다시 주문하도록 안내합니다.

## UC-02 웹 사전 주문 고객 안내

```mermaid
flowchart LR
    A[1. 웹 사전 주문<br/>고객이 앱/웹에서 메뉴 선택] --> B[2. 주문 서버 저장<br/>주문번호·회원정보·주문상태 저장]
    B --> C[3. 매장 방문<br/>고객이 로봇 앞에 접근]
    C --> D[4. 본인/주문 확인<br/>얼굴 인식 또는 주문번호/음성 확인]
    D --> E[5. 주문 정보 조회<br/>DB에서 주문 내역과 준비 상태 확인]
    E --> F{주문 정보가 확인되는가?}
    F -- 네 --> G[6. 준비 상태 안내<br/>주문하신 음료가 준비 중입니다]
    G --> H[7. 픽업 위치 안내<br/>픽업대에서 받아주세요]
    F -- 아니오 --> I[재확인 요청<br/>주문번호 재입력·얼굴 재인식·직원 호출]
    I --> D
    B -. 장기 미방문 .-> J[예외 처리<br/>주문 자동 취소 또는 관리자 알림]
```

### UC-02 핵심 설명

- 고객이 웹에서 메뉴를 사전 주문합니다.
- 주문 정보는 주문 서버와 DB에 저장됩니다.
- 고객이 매장에 방문하면 로봇이 얼굴 인식, 주문번호, 음성 확인 등으로 주문을 조회합니다.
- 주문 정보가 확인되면 음료 준비 상태와 픽업 위치를 안내합니다.
- 주문 확인이 실패하면 주문번호 재입력, 얼굴 재인식, 직원 호출 등 재확인 절차를 진행합니다.
- 장시간 고객이 방문하지 않으면 주문 상태를 자동 갱신하거나 관리자에게 알립니다.

## UC-03 얼굴 인식 기반 단골 고객 응대

```mermaid
flowchart LR
    A[1. 등록 고객 입장<br/>얼굴 등록·개인정보 동의 완료] --> B[2. 카메라 얼굴 감지]
    B --> C[3. Face Embedding 추출<br/>얼굴 특징 벡터 생성]
    C --> D[4. 등록 고객 DB 비교<br/>얼굴 벡터와 주문 이력 조회]
    D --> E{매칭 신뢰도 충분한가?}
    E -- 네 --> F[5. 개인화 인사<br/>오랜만에 오셨네요]
    F --> G[6. 선호 메뉴 추천<br/>항상 주문하시던 아이스 아메리카노로 준비할까요?]
    G --> H{추천 메뉴를 주문할까?}
    H -- 네 --> I[7. 주문 확인 및 서버 저장]
    H -- 거절 --> J[일반 음성 주문 전환]
    E -- 아니오/불확실 --> J
    J --> K[UC-01 매장 직접 음성 주문 흐름으로 진행]
```

### UC-03 핵심 설명

- 사전에 얼굴 등록과 개인정보 활용 동의를 완료한 고객이 매장에 입장합니다.
- 로봇 카메라가 얼굴을 감지하고 Face Embedding을 추출합니다.
- 등록 고객 DB와 비교하여 매칭 신뢰도가 충분한지 판단합니다.
- 신뢰도가 충분하면 주문 이력과 선호 메뉴를 기반으로 개인화 인사와 추천 주문을 제공합니다.
- 고객이 추천 메뉴를 수락하면 주문 확정 절차로 이어집니다.
- 신뢰도가 낮거나 고객이 거절하면 일반 음성 주문 흐름으로 전환합니다.

## 설계 기준

- 주문 오류를 줄이기 위해 모든 주문은 확인 단계를 거칩니다.
- 얼굴 인식 결과가 불확실하면 개인화 응대를 하지 않고 일반 주문으로 전환합니다.
- 사용자가 처음 보더라도 `고객 행동 → 로봇 인식 → AI 판단 → 안내/주문 처리 → 예외 처리` 흐름을 이해할 수 있도록 구성했습니다.
