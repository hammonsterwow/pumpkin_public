# 메뉴 카탈로그 연동 규칙

## 목적

프로젝트에서 메뉴를 사용하는 새 기능은 `config/menu_catalog.json`을 메뉴 정보의 기준 원본(Single Source of Truth)으로 사용한다.

## 공식 메뉴 ID

| menu_id | 메뉴 | 가격 | 제공 온도 |
|---:|---|---:|---|
| 1 | 아메리카노 | 3000 | ICE, HOT |
| 2 | 카페라떼 | 4000 | ICE, HOT |
| 3 | 바닐라라떼 | 4500 | ICE, HOT |
| 4 | 레몬에이드 | 4500 | ICE |
| 5 | 딸기스무디 | 5000 | ICE |

## 새 기능 개발 규칙

1. 새 기능에서 메뉴를 식별할 때는 `menu_id`를 우선 사용한다.
2. 메뉴명, 가격, 제공 온도, 판매 여부, 설명, 이미지 경로를 기능별 코드에 중복 하드코딩하지 않는다.
3. 메뉴 정보가 필요하면 `config/menu_catalog.json` 또는 이를 읽어 제공하는 공용 메뉴 API/서비스를 사용한다.
4. 주문, 고객 선호 메뉴, 관리자 기능, 앱 기능 등 DB에 메뉴 관계를 저장할 때는 `menu_id`를 기준 키로 사용한다.
5. 주문 기록에는 과거 주문 당시의 표시용 메뉴명과 가격을 함께 저장할 수 있으나, 메뉴 식별 기준은 `menu_id`로 유지한다.
6. NLU는 기존 학습 결과와 호환성을 위해 메뉴명을 문자열로 출력할 수 있다. NLU 결과를 실제 주문 데이터로 변환할 때 메뉴명을 카탈로그의 `name`/`aliases`와 매칭하여 `menu_id`로 변환한다.
7. 새 메뉴를 추가하거나 가격·온도 정책 등을 변경할 때는 우선 `config/menu_catalog.json`을 수정한다.

## 기존 코드 호환 정책

현재 고객 앱 일부 코드는 `americano`, `caffe-latte`와 같은 문자열 `id`와 메뉴명을 기준으로 단골 고객 기능을 구현하고 있다. 진행 중인 단골 고객 브랜치와 충돌하지 않도록 기존 코드를 즉시 일괄 변경하지 않는다.

기존 기능을 수정하거나 리팩터링할 때는 단계적으로 숫자 `menu_id` 기준으로 전환한다. 새로 작성하는 기능은 처음부터 공식 `menu_id`를 사용한다.

## 이미지

메뉴 이미지가 준비되기 전에는 `image: null`을 허용한다. 향후 이미지를 추가할 때도 앱·웹에 이미지를 각각 중복 저장하지 않고, 카탈로그의 이미지 경로를 기준으로 공용 제공하는 방향을 사용한다.
