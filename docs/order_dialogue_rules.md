# 주문 대화 및 처리 규칙 설계

## 1. 목적

다음 두 상황을 안정적으로 처리하기 위한 시스템 규칙을 정의한다.

1. 한 문장에 두 개 이상의 메뉴가 포함된 복합 주문
2. 메뉴, 수량, 온도 중 일부 정보가 누락된 불완전 주문

모델은 정보를 추출하고, 대화 관리기는 이 문서의 규칙에 따라 주문 항목을 구성하고 부족한 정보를 질문한다.

---

## 2. 기본 주문 구조

모든 주문은 메뉴가 하나인 경우에도 `items` 배열로 관리한다.

```json
{
  "session_id": "string",
  "intent": "ORDER",
  "items": [
    {
      "item_id": 0,
      "menu": "아메리카노",
      "quantity": 1,
      "temperature": "ICE",
      "missing_slots": [],
      "confidence": {
        "menu": 0.93,
        "quantity": 0.89,
        "temperature": 0.91
      }
    }
  ],
  "waiting_for": null,
  "dialogue_state": "CONFIRMING",
  "robot_response": "아이스 아메리카노 1잔 맞으신가요?"
}
```

### 슬롯 값

- `menu`: 표준 메뉴명 또는 `null`
- `quantity`: 1 이상의 정수 또는 `null`
- `temperature`: `ICE`, `HOT`, `NONE` 중 하나 또는 `null`
- `missing_slots`: 추가 질문이 필요한 슬롯 목록

`NONE`은 온도 선택이 필요하지 않은 메뉴라는 뜻이고, `null`은 아직 값을 모른다는 뜻이다.

---

## 3. 메뉴 정책

### 3.1 온도를 반드시 확인하는 메뉴

- 아메리카노
- 카페라떼
- 바닐라라떼
- 카라멜마키아토
- 카페모카
- 초코라떼
- 녹차라떼

온도가 입력되지 않으면 `temperature = null`로 두고 질문한다.

### 3.2 차가운 음료로 고정되는 메뉴

- 레몬에이드
- 딸기스무디

이 메뉴들은 별도 온도 질문 없이 `temperature = ICE`로 채운다.

### 3.3 메뉴 별칭 정규화

| 사용자 표현 | 표준 메뉴명 | 추가 정보 |
|---|---|---|
| 아아 | 아메리카노 | 온도 ICE |
| 뜨아 | 아메리카노 | 온도 HOT |
| 아메 | 아메리카노 | 온도 미지정 |
| 라떼 | 카페라떼 | 온도 미지정 |
| 카페라테 | 카페라떼 | 표기 통일 |
| 바닐라라테 | 바닐라라떼 | 표기 통일 |

메뉴 별칭은 모델 출력 후에도 한 번 더 정규화한다.

## 4. 복합 주문 처리 규칙

### 4.1 복합 주문 판단

다음 중 하나에 해당하면 복합 주문 후보로 판단한다.

- 메뉴 엔티티가 두 개 이상 검출됨
- 연결 표현이 포함됨
- 쉼표로 주문 항목이 구분됨

초기 분리 표현:

- `이랑`
- `랑`
- `하고`
- `그리고`
- `와`
- `과`
- `,`
- `또`
- `추가로`

예시:

```text
아메리카노 한 잔이랑 라떼 두 잔 주세요
```

분리 결과:

```json
[
  "아메리카노 한 잔",
  "라떼 두 잔 주세요"
]
```

### 4.2 분리 금지 조건

다음 경우에는 연결 표현이 있어도 분리하지 않는다.

- 연결 표현 뒤에 새로운 메뉴가 없음
- `그리고요`, `또요`처럼 의미 없는 후행 표현만 있음
- 수정 문장 내부에서 사용됨

### 4.3 주문 항목 구성

각 메뉴를 기준으로 가장 가까운 수량과 온도를 같은 `item_id`에 연결한다.

```text
아이스 아메리카노 한 잔이랑 따뜻한 라떼 두 잔
```

```json
{
  "items": [
    {
      "item_id": 0,
      "menu": "아메리카노",
      "quantity": 1,
      "temperature": "ICE"
    },
    {
      "item_id": 1,
      "menu": "카페라떼",
      "quantity": 2,
      "temperature": "HOT"
    }
  ]
}
```

### 4.4 공통 수식어

`둘 다 아이스로`, `전부 따뜻하게`, `각각 한 잔씩`처럼 적용 대상이 명확한 표현만 여러 항목에 공통 적용한다.

대상이 불명확하면 임의 적용하지 않고 다시 질문한다.

---

## 5. 빈 슬롯 판단 규칙

필수 슬롯은 다음 순서로 검사한다.

1. `menu`
2. `quantity`
3. `temperature`

단, 온도 고정 메뉴는 온도를 자동으로 채우고 질문하지 않는다.

### 메뉴 누락

```text
어떤 메뉴를 주문하시겠어요?
```

### 수량 누락

```text
아메리카노 몇 잔 주문하시겠어요?
```

수량을 말하지 않았다고 해서 임의로 1잔으로 처리하지 않는다.

### 온도 누락

```text
아메리카노는 아이스로 드릴까요, 따뜻하게 드릴까요?
```

### 낮은 신뢰도

값이 있어도 confidence가 기준보다 낮으면 누락과 동일하게 재확인한다.

초기 기준:

- intent: 0.60
- menu: 0.60
- quantity: 0.55
- temperature: 0.55

이 기준은 검증 데이터 결과에 따라 조정한다.

---

## 6. 빈 슬롯 질문 순서

복합 주문에서는 다음 순서로 질문한다.

1. `item_id`가 작은 항목부터 처리
2. 한 항목 안에서는 `menu → quantity → temperature`
3. 현재 항목이 완성되면 다음 항목으로 이동

예시:

```text
사용자: 아메리카노랑 따뜻한 라떼 두 잔 주세요
로봇: 아메리카노 몇 잔 주문하시겠어요?
사용자: 한 잔이요
로봇: 아메리카노는 아이스로 드릴까요, 따뜻하게 드릴까요?
사용자: 아이스로요
로봇: 아이스 아메리카노 1잔, 따뜻한 카페라떼 2잔 맞으신가요?
```

---

## 7. 후속 응답 처리

후속 응답은 현재 `waiting_for` 슬롯을 우선하여 해석한다.

### 7.1 수량 표현

| 표현 | 값 |
|---|---:|
| 한 잔, 하나, 한 개, 1잔 | 1 |
| 두 잔, 둘, 두 개, 2잔 | 2 |
| 세 잔, 셋, 세 개, 3잔 | 3 |
| 네 잔, 넷, 네 개, 4잔 | 4 |
| 다섯 잔, 다섯 개, 5잔 | 5 |

1~20 범위의 정수를 허용한다. 0 이하의 값은 거부한다.

### 7.2 온도 표현

ICE:

- 아이스
- 차갑게
- 시원하게
- 냉으로

HOT:

- 따뜻하게
- 뜨겁게
- 핫으로
- 온으로

### 7.3 메뉴 응답

메뉴 사전과 별칭 사전을 사용해 정규화한다. 메뉴판에 없는 입력은 확정하지 않고 다시 질문한다.

```text
해당 메뉴를 찾지 못했습니다. 메뉴 이름을 다시 말씀해주세요.
```

### 7.4 여러 슬롯을 한 번에 보완

사용자가 `두 잔이고 아이스로요`처럼 여러 정보를 한 번에 말하면 현재 항목의 수량과 온도를 함께 채울 수 있다.

---

## 8. 전체 항목 적용 표현

다음 표현은 대상이 명확할 때 모든 해당 항목에 적용한다.

- `둘 다 아이스로`
- `전부 따뜻하게`
- `각각 한 잔씩`
- `전부 두 잔씩`

예시:

```text
사용자: 아메리카노랑 라떼 주세요
로봇: 아메리카노 몇 잔 주문하시겠어요?
사용자: 둘 다 한 잔씩 아이스로요
로봇: 아이스 아메리카노 1잔, 아이스 카페라떼 1잔 맞으신가요?
```

---

## 9. 확인·수정·취소

### 최종 확인

모든 필수 슬롯이 채워진 경우에만 최종 확인으로 이동한다.

```text
아이스 아메리카노 1잔, 따뜻한 카페라떼 2잔 맞으신가요?
```

### 긍정 응답

- 네
- 예
- 맞아요
- 맞습니다
- 응
- 그래
- 그렇게 주세요

처리 결과:

```text
주문을 접수했습니다.
```

### 부정 응답

- 아니요
- 아니
- 틀렸어요
- 잘못됐어요

처리 결과:

```text
어떤 내용을 변경할까요? 메뉴, 수량 또는 온도를 말씀해주세요.
```

### 수정 요청

수정 대상이 명확하면 해당 항목만 변경한다. 대상이 불명확하면 메뉴를 다시 확인한다.

### 전체 취소

- 주문 취소
- 전부 취소
- 안 살게요
- 처음부터 다시

`처음부터 다시`는 주문 상태를 초기화한다.

---

## 10. 대화 상태

| 상태 | 의미 |
|---|---|
| `IDLE` | 주문 입력 대기 |
| `ANALYZING` | 주문 분석 중 |
| `FILLING_SLOT` | 빈 슬롯 보완 중 |
| `CONFIRMING` | 최종 확인 중 |
| `MODIFYING` | 주문 수정 중 |
| `COMPLETED` | 주문 확정 완료 |
| `CANCELLED` | 주문 취소 완료 |
| `ERROR` | 처리 실패 또는 복구 필요 |

상태 전이:

```text
IDLE → ANALYZING
ANALYZING → FILLING_SLOT 또는 CONFIRMING 또는 ERROR
FILLING_SLOT → FILLING_SLOT 또는 CONFIRMING
CONFIRMING → COMPLETED 또는 MODIFYING 또는 CANCELLED
MODIFYING → CONFIRMING 또는 FILLING_SLOT 또는 CANCELLED
```

---

## 11. 예외 처리

- 같은 슬롯에서 2회 연속 실패하면 선택지를 명확하게 제시한다.
- 3회 연속 실패하면 화면 직접 선택 또는 직원 호출로 전환한다.
- 한 주문의 최대 메뉴 수는 초기에는 5개로 제한한다.
- 한 항목의 최대 수량은 20잔으로 제한한다.
- 동일 메뉴와 동일 온도는 수량을 합친다.
- 동일 메뉴라도 온도가 다르면 별도 항목으로 유지한다.

## 13. 구현 우선순위

### 1차

- `items` 배열 도입
- 실제 메뉴판 기반 메뉴 사전 구성
- 메뉴 별칭 정규화
- 연결어 기반 복합 주문 분리
- 메뉴별 온도 정책 적용
- `missing_slots` 계산
- `waiting_for` 상태 관리
- 수량·온도 후속 응답 처리
- 최종 확인과 긍정·부정 처리

### 2차

- 수정 및 부분 취소
- 전체 항목 적용 표현
- 낮은 confidence 재확인
- 중복 메뉴 병합
- 재질문 횟수와 오류 복구

### 3차

- BIO+CRF 기반 복합 주문 추출 모델
- 메뉴와 수량·온도의 관계 분류
- 규칙 기반 결과와 모델 결과 결합
